# 2026-08-26 — 주문 이유 입력 UX + 리포트 권유 카드 제거

## 무엇을 했나

1. **이유 미선택 시 흔들림** — `매수하기`가 비활성이라 눌러도 아무 일이 없던 것을, 눌리게 하고 이유 칩 행을 흔들도록 바꿈. 라벨 옆 `필수`를 붉게.
2. **`기타` 주관식 근거** — 칩 6번째로 `기타` 추가, 선택 시 100자 한 줄 입력. 자유문은 `Trade.note`에 분리 저장.
3. **리포트 구독 예고 CTA 제거** — 회고 저장 때마다 뜨던 카드를 없앰.

## 왜 스펙을 뒤집었나 (중요)

`design-prompts/10-order-judgment.md`는 이번에 바꾼 두 가지를 **명시적으로 금지**하고 있었다.

- `:20` "자유입력 텍스트 없음 (세션 종료 후 회고 메모가 따로 있음)"
- `:31` "이유 칩 1개 이상 필수 — 미선택 시 CTA 비활성"

게다가 자유입력은 구스펙 `05-simulation.md:44`에 있던 것을 10번 스펙이 **의도적으로 걷어낸** 것이다. 즉 이번 변경은 그 결정으로의 되돌림이다. 되돌린 근거:

- **비활성 CTA는 '왜 안 되는지'를 못 알려준다.** `miss` 힌트(`OrderSheet.tsx:216`)가 이미 있었지만, 사용자가 실제로 겪은 건 "버튼을 눌렀는데 아무 일도 안 일어남"이었다. 힌트는 버튼 아래에 있고 회색 버튼은 읽히지 않았다.
- **가격·수량은 비활성을 유지했다.** 값이 없으면 주문 자체가 성립하지 않는 항목과, 사용자가 '왜 필요한지'를 배워야 하는 항목을 구분한 것. 흔들림을 앱 전체 규칙으로 승격시키지 않았다 — `Review.tsx:139`(감정 선택) 등 다른 5곳의 `disabled` 관례는 그대로다.
- **5범주로 안 잡히는 근거를 버리고 있었다.** `docs/차티앱수익화방향.md:96-98`의 원안도 "유형 선택 + 선택적 자유입력" 구조를 요구한다. 다만 원안의 세부 34개 항목(2단 구조)까지는 가지 않고 `기타` 하나로 최소 탈출구만 냈다.

## 설계 판단 3건

**1. 자유문은 `reasons[]`가 아니라 `note`로 분리.** `reasonDist()`(`report.ts:141`)가 문자열을 그대로 Map 키로 쓴다. 자유문을 섞으면 근거 분포가 세션마다 유일값 1개짜리 칩으로 파편화되고, 렌더하는 `.dist-chip`은 `height: 30px` 고정에 잘라내기가 없어 긴 문장 하나로 카드가 깨진다. `reasons`에는 `'기타'` 리터럴만 들어간다.
   - 대안(`reasons`에 넣고 `reasonDist`에서 접두사 필터)은 1줄로 더 싸지만, "reasons = 닫힌 범주 집합" 불변식이 깨지고 필터 규약을 모든 미래 소비자가 복제해야 한다. 실패 모드가 "한 군데 빼먹으면 조용히 오집계"인 쪽 대신 "컴파일 에러"인 쪽을 택했다.

**2. `note`를 읽는 화면을 같은 변경에 넣었다.** `Archives/2026-08-05-ponytail-audit.md:16` — 매매 이유 배관이 "수집·저장만 하고 어디에도 표시 안 됨"을 이유로 통째 삭제된 적이 있다. 개별 `Trade`를 보여주는 화면이 저장소에 하나도 없으므로, 회고 리포트 '이번 세션 판단 근거' 카드에 인용 줄을 함께 넣었다. 기록(`History.tsx`) 노출은 그 파일을 다음에 만질 때로 미룸(`proposal.md:65` 규약 6).

**3. 흔들림만 WAAPI(`Element.animate`).** 이 레포 애니메이션 12종은 전부 `index.css` `@keyframes`이고 JS 구동은 이번이 처음이다. 예외로 둔 이유는 **제출 실패마다 재시작이 보장돼야** 하는데, 클래스 토글은 재생 중 재클릭에서 재시작되지 않고 `key` remount는 흔들 대상에 controlled input(`기타` 입력)이 들어있어 못 쓰기 때문. `getAnimations().forEach(cancel)`을 반드시 선행 — 없으면 연타 시 Animation이 중첩돼 튄다. `OrderSheet.tsx`에 `ponytail:` 주석으로 천장·승격 경로를 남김.
   - 참고: input 없는 요소의 애니메이션 재시작은 `Simulation.tsx:435`의 `key={toast.id}` 패턴이 이 레포의 기존 해법이다.

## 리포트 권유 카드

회고를 저장할 때마다 정확히 1회 렌더됐고(`Review.tsx`의 `if (report)`가 유일 조건), **무거래·관찰 0개인 빈 리포트 위에도** 그대로 떴다. 이미 신청한 사용자에게도 본체는 매번 재노출됐다(`disabled`가 제어한 건 버튼뿐).

리포트 구독 기능 자체가 아직 없으므로 빈도 조절이 아니라 **노출 중단**을 택했다. `joinWaitlist` 액션은 호출부가 사라져 함께 제거. `.cta-card`/`.cta-skip` CSS도 사용처가 이 한 곳뿐이라 제거.

**`waitlistAt` state는 남겼다.** 기존 사용자가 이미 기록한 값이고, `sync.ts:81` `pickState` 슬라이스에서 빼면 직렬화 결과가 바뀌어 `stateUpdatedAt`이 갱신되고 LWW로 다른 기기의 진짜 기록(customs·activeSim)을 이길 수 있다. 슬라이스 키 4개를 고정하는 회귀 테스트를 `sync.test.ts`에 추가.

**대가**: 지불의사 신호의 신규 수집이 멈춘다. 저장소에 analytics가 없어 원래도 지표는 `waitlistAt` 불리언 하나뿐이었다. 리포트 기능을 낼 때 CTA와 **노출 빈도 정책을 함께** 되살릴 것 — '매 세션'은 재현 금지.
