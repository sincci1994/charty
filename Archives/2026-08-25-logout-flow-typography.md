# 2026-08-25 — 로그아웃 플로우 정상화 + 타이포 축소·레이아웃 내성

## 작업 개요

**① 로그아웃 수정** — 로그아웃해도 화면이 안 바뀌고 계정 기록이 기기에 그대로 남던 문제.
"지우기"와 "이동"이 **둘 다** 필요했다(웰컴 게이트가 3조건 AND라 하나만으론 안 열림).
설계 후 적대적 검증(9-에이전트 워크플로)에서 **자체 수정이 만든 신규 데이터 손실 3건**이 나와 되돌려 반영.
**② 타이포 한 단계 축소 + 찌부 내성** — 폰에서 글자가 커 줄 어긋남·위젯 찌부가 보인다는 보고.

## 진단 기록

### 로그아웃이 "이동만" 또는 "지우기만"으론 안 되는 이유

셸 웰컴 게이트(`shell.tsx`)는 `!welcomed && records.length === 0 && !activeSim` **3조건 AND**다.
로그아웃 후 `welcomed: true`가 남아 있으면 `/welcome`으로 보내도 되돌아오고, 이동만 시켜도 게이트가 안 열린다.
그래서 로컬 계정 데이터를 비우면서 동시에 명시적으로 이동시켜야 한다.

### 적대적 검증이 잡아낸, 1차 수정이 만든 손실 3건

1. **`welcomed`가 동기화 슬라이스에 있었다** (blocker). 와이프로 `stateUpdatedAt=0`이 된 직후
   `/welcome`의 아무 버튼이나 누르면 `setWelcomed()`가 **내용은 빈** 슬라이스에 최신 스탬프를 찍는다.
   재로그인 시 LWW 비교에서 로컬이 이겨 **서버의 진짜 `customs`·진행 세션을 덮어 지운다** —
   "로그아웃 → 다시 로그인"이라는 가장 평범한 왕복만으로. `welcomed`는 theme·coach와 같은 기기 로컬
   게이트이므로 `SyncedState`에서 제거. 다른 기기 중복 노출은 게이트의 `records.length === 0` 조건과
   Welcome의 세션 리다이렉트가 이미 막는다.
2. **`syncRecords`가 upsert 에러를 안 봤다.** SELECT는 통과했는데 회선이 끊겨 upsert가 실패해도
   `merged`(non-null)를 반환 → 로그아웃 플러시 가드가 "올라갔다"고 믿고 로컬을 지운다.
   사용자에겐 "기록은 계정에 저장돼 있다"고 말한 뒤 지우는 셈.
3. **`pushState`가 `Promise<void>`라 실패를 알릴 수단이 없었다.** `customs`·`activeSim`은 records에서
   파생 불가라 `state` 행이 유일본 → 조용히 영구 소실. `boolean` 반환으로 바꿔 플러시 가드에 편입.

### 비자발적 SIGNED_OUT은 지우면 안 된다

`auth-js`는 세션 만료·리프레시 실패에서도 `_removeSession → SIGNED_OUT`을 쏜다(크로스탭 브로드캐스트 포함).
그 경로엔 사용자 확인도 플러시도 없고, **하필 오프라인이라 로컬이 유일본일 확률이 가장 높다**.
그래서 와이프는 동의를 받은 More 버튼에서만 하고, shell의 SIGNED_OUT은 프로필 미러만 정리한다.
(1차 설계는 "모든 로그아웃이 지나는 유일한 길목"이라는 이유로 shell에 뒀다가 이 지적으로 되돌림.)

### 대사 왕복 중 로그아웃 → 지운 기록이 부활

`syncRecords`의 `merged`는 **항상 로컬 스냅샷을 포함**한다. 콜드스타트 동기화가 진행 중일 때 로그아웃하면
그 응답이 와이프 뒤에 도착해 `applySync(merged)`로 계정 기록 전체를 스토어·persist에 되살린다.
→ `await` 재개마다 `charty:uid` 재확인(`stale()`) 가드 추가.

### 기타 확인 사실

- `signOut()`은 서버 호출이 실패해도 `_removeSession()`을 거쳐 SIGNED_OUT을 쏜다 → 오프라인에서도 안 갇힌다.
- 기본 scope는 `global`이라 **다른 기기 세션까지 끊는다** → `local`로 변경.
- `charty:uid`가 로그아웃 후에도 남으면, 이후 게스트 데이터가 다음 로그인 때 계정 전환 가드에 확인 없이 지워진다 → 삭제.
- zustand persist는 `set()` 스택 안에서 `localStorage.setItem`을 **동기 호출**한다
  (`zustand/esm/middleware.mjs`) → 와이프 후 `removeItem('charty')` 불필요, 덕분에 theme·coach 보존.
- 게스트→계정 이어받기는 기존 `syncRecords` + state 시드 경로가 이미 처리 → **코드 변경 0줄**.

### 타이포 — 전체 축소가 답이 아닌 이유

font-size 선언 285개 중 **190개가 이미 8~14px**. 일괄 배율은 작은 라벨을 못 읽게 만든다.
"크다"고 느껴질 15px 이상 57개만 ×0.92(`15→14 16→15 17→16 18→17 20→18 22→20 28→26 32→29 33→30`).

### 찌부·어긋남의 실제 메커니즘

- **찌부** = 텍스트를 담은 위젯의 `height` 고정. 글자가 커지면 눌린다 → `min-height`로 전환(16개).
  아이콘·스위치·핸들 등 장식 높이는 그대로.
- **어긋남/겹침** = 홈 자산 금액. 금액 열이 `min-width: 0`이라 **열은 조용히 줄고 글자만 넘쳐** 아바타를 덮었다.
  `clamp(…, 7.5vw, …)`는 뷰포트 기준이라 안드로이드 텍스트 배율이 그 위에 다시 곱해지면 무력.
  → `min-width: min-content`로 열이 필요 폭을 주장하게 하고 아바타가 양보(`flexShrink: 1`, 최소 40px).

## 남은 것 / 미해결

- **실기기 증상 미확증**: 사용자 폰은 글자 크기 기본값인데 증상이 보인다고 함. 그러나 하니스에서는
  기본 배율(320/360/390)에서 재현되지 않았고(Pretendard 폴백 폭 차이 7%도 무관), 1.15배 이상에서만 재현.
  이번 변경이 덮을 가능성은 높으나 **문제 화면 스크린샷 1장이 있어야 확증** 가능.
- **실계정 OAuth 왕복 미검증**: 게스트 기록이 실제 Google 계정에 올라가는 최종 왕복은 코드 추적과
  네트워크 호출 순서까지만 확인(로컬은 합성 세션). 배포 후 실기기 확인 필요.
- **멀티탭 미지원**: 한 탭에서 로그아웃해도 다른 탭은 안 비워진다(모바일 앱 기준이라 의도적 보류).
  필요해지면 `charty:uid` 부재를 자발적 로그아웃 신호로 쓰는 방식이 후보 — 단 게스트(uid 원래 없음)를
  오검출하지 않을 양성 신호가 필요.
- `resetAll`의 미완 리셋(`customs`/`welcomed`/`waitlistAt` 미삭제)은 기존 갭으로 남음. `wipeLocal` + `clearRemote` 조합으로 정리 가능.
- 계정 전환 가드는 이제 "세션이 SIGNED_OUT 없이 사라진 경우"의 보험으로만 남음(거의 사문).
- 레포 루트 `icon.png`·`icon_empty.png`는 8/24 아이콘 작업 이후 계속 untracked 상태.
