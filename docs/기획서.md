# 차티(Charty) 기획서

> 개인 개발 로드맵용 문서. 코드 기준: `charty-web` v0.1.0 (2026-08 기준, Next.js 전환 후).
> 인프라 개편(Next.js + Supabase 7단계)은 별도 개편 계획을 따른다 — 이 문서는 제품 로드맵.
> 화면별 상세 명세는 [`design-prompts/`](../design-prompts/) 참조.

---

## 1. 제품 개요

**차티는 과거 차트 데이터로 빠르게 모의투자를 반복하는 연습 앱이다.**

### 문제의식
- 실전으로 거래 스타일을 검증하려면 시간이 오래 걸리고 비싸다. 스윙 한 사이클에 몇 주, 장기 포지션은 몇 달이 필요하다.
- 지나간 차트로 복기할 때는 이미 결과를 알고 본다. "저기서 샀어야지"는 연습이 아니다.

### 목표
1. **자신에게 맞는 거래 스타일 찾기** — 단타/스윙/장기를 짧은 시간 안에 여러 번 경험하고, 기록으로 비교한다.
2. **당시 상황을 객관적으로 보는 시각** — 종목과 시점을 숨긴 차트 앞에서, 결과를 모르는 상태로 판단하는 훈련.

### 타깃
개인 트레이딩 연습자(우선은 개발자 본인). 비로그인도 브라우저만으로 전체 동작(local-first).

### 거래 스타일 프리셋 (`src/lib/data.ts`)
| 스타일 | 거래 기간 | 차트 간격 | 캔들 수 |
|---|---|---|---|
| 단타 | 1일 | 5분 | 78 |
| 스윙 | 14일 | 1시간 | 98 |
| 장기투자 | 60일 | 4시간 | 120 |
| 커스텀 | 자유 (기간×단위) | 5분~1주 7개 중 택 1 (1분은 데이터 없어 비활성) | 환산 계산 |

### 시뮬레이션 규칙 (`src/lib/engine.ts`)
- 시작 잔고 100만. 지정가 주문만 지원 (다음 캔들의 고가~저가 범위에 들어오면 체결).
- **현물 전환 확정 (2026-08)**: 매수/매도만 제공, 매도 상한 = 보유수량. 선물 문법(Long/Short·Open/Close)은 타깃(초보)에게 진입장벽이라 폐기 — R5 구현과 함께 UI 전환. 현재 구현은 아직 LONG/SHORT 각 1포지션 + 숏 증거금 잠금.
- 마지막 캔들 도달 또는 [End Now] 시 미체결 취소 + 잔여 포지션 종가 청산.
- 레버리지·수수료·슬리피지·시장가·숏 없음 (의도적 단순화. 숏·레버리지는 R9 Future 모드로 별도 검토).

### 데이터
- `charty-web/public/data/` — 6종목(QQQ·SPY·AAPL·NVDA·TSLA·MSFT) × 4개 기본 타임프레임(5m·1h·1d·1w) 정적 JSON + 경제지표(`econ.json`)·뉴스(`news.json`).
- 15m/30m/4h는 파일 없이 브라우저에서 5m/1h 리샘플로 파생 (`resampleCandles`).
- 세션 시작 시 종목 랜덤 선택 + 지표 워밍업(EMA 200 + 과거 60캔들)을 확보한 랜덤 시작점.

### 기록 구조 (`src/types.ts`)
- 회고 저장 시 `SimRecord`(스타일·종목·시작/종료 잔고·수익률·거래 수·감정·메모)가 기록에 추가되고 잔고 이월.
- 승률·평균 수익률·스트릭·자산 추이는 기록에서 즉석 계산.
- 개별 체결 내역(`Trade[]`: 단가·수량·손익)은 `SimRecord.trades`로 **보존됨** ([R0-1](#5-로드맵-선행-과제-r0) ✅). 매매 이유 등 판단 데이터는 아직 없음 → R5.

## 4. 확장 로드맵

R = Roadmap. 번호는 등록 순이고, 착수 순서는 [7장 마일스톤](#7-버전-마일스톤)을 따른다.
R5~R8은 수익화 퍼널([차티앱수익화방향.md](./차티앱수익화방향.md) 16장·18장)을 구현하는 기능이다.

### R1. 멀티 타임프레임 차트

> ✅ 구현됨 (`4c332ff` — 멈춘 차트 타임프레임 전환 + 보조지표 설정). 선행이던 [R0-3]도 완료.

현재는 세션의 차트 간격(예: 장기투자 = 4시간봉) 하나로만 본다.

- **시간 진행은 그대로**: [다음 캔들]은 세션 간격(4시간) 단위로 유지.
- **멈춘 차트에서 타임프레임 전환**: 현재 시점까지의 데이터를 다른 시간봉(15분/1시간/1일 등)으로 다시 그려서 볼 수 있게.
- 필요 작업:
  - 동일 종목·동일 구간의 타 타임프레임 데이터 슬라이싱 (현재 커서 시각 이후는 절대 노출 금지)
  - `Chart.tsx`에 타임프레임 셀렉터 UI
  - 선행: [R0-3] 타임프레임 데이터 확충

### R2. 시뮬레이션 News 기능

> ✅ 구현됨 (`4c332ff` — 경제지표·헤드라인 탭, GDELT·ALFRED 파이프라인). 잔여: 시대 추정 힌트 필터 기준의 지속 검증.

시뮬레이션 상단의 News 탭에 **해당 차트 시간대에 실제로 존재했던 경제지표**를 보여준다.

- 내용: 지표별 이전값 / 발표값 (예: 기준금리, FOMC 점도표, CPI, 고용지표).
- **블라인드 정책이 핵심**: 종목을 숨겼는데 뉴스로 시대를 추정할 수 있으면 무의미.
  - 연도·특정 사건명·인물명 등 시대 추정 힌트 제거.
  - 수치와 방향성(이전값 대비 상승/하락)만 노출.
- 필요 작업:
  - 경제지표 히스토리 데이터셋 수집·정제 (정적 JSON, 서버 없음 유지)
  - 시대 추정 힌트 필터링 기준 정의
  - News 탭 UI (`Simulation.tsx`)

### R3. 종합 리포트
기록이 충분히 쌓이면, **"거시경제 상황이 X일 때 거래 스타일 Y가 너에게 잘 맞는다"**를 데이터로 보여준다.

- 승률 높았던 세션들의 공통점 분석: 당시 거시 지표 상태(금리 방향, 지표 서프라이즈 등) × 거래 스타일 × 매매 이유.
- 현재 경제 시장이 그 조건과 유사한지 표시.
- 선행 조건:
  - [R0-1] 세션별 `Trade[]` 보존 — 매매 이유·체결 단위 분석의 원천 데이터
  - R2의 거시경제 데이터셋 — 세션 구간과 지표 상태를 연결

### R4. 스피드 퀴즈 (후순위)
차트를 보고 롱/숏을 즉답하는 퀴즈. `/practice`에 카드만 존재.

- **Win/Lose 판정 기준이 미정**이라 후순위: 몇 캔들 뒤를 기준으로? 등락폭 임계값은? 횡보면?
- 개념 설계가 끝나면 착수.

### R5. 판단 기록 확장 (수익화 MVP 1단계)

> ✅ 구현됨 (2026-08-09, 현물 전환과 함께) — 목업 브리프: [design-prompts/10-order-judgment.md](../design-prompts/10-order-judgment.md)

주문 시점의 판단을 구조화해서 수집한다. 현재는 가격·수량만 저장되고 판단 데이터는 전무하다.

- **주문 시트에 추가 입력**: 매매 이유 칩 5개(수익화방향 5장의 5범주를 범주 레벨로 축약 — R7 지표가 태그 입도를 안 씀) **1개 이상 필수·복수 선택**, 선택적 손절가·목표가. 확신도(1~5)는 마찰 대비 가치가 낮아 제외(R7 4지표가 확신도를 안 씀 — 필요 시 R8 챌린지에서 재검토). 추가 마찰은 탭 1회.
- **손절가·목표가는 기록만 한다** — 엔진 자동 체결 없음. 목적이 "계획 vs 실제 실행 차이"(손절 준수율) 측정이므로 엔진은 건드리지 않는 게 맞다.
- **현물 UI 전환을 R5 구현과 함께 진행** (기술 노트, 조사 완료):
  - 매핑: 매수=`OPEN_LONG`, 매도=`CLOSE_LONG` — 엔진 Close가 보유 수량 차감 구조라 현물 매도와 동일, 엔진·SHORT 테스트는 무수정 유지(Future 모드 회귀 방어선)
  - 함정: OrderSheet의 `${oc}_${dir}` 문자열 결합을 리터럴로 대체할 것(매도가 `OPEN_SHORT`로 새는 사고 방지) / `Style` 타입의 `'LONG'`(장기투자)과 혼동 금지 / persist된 진행 세션의 SHORT 잔존 마이그레이션 필요
- 필요 작업:
  - `Order`/`Trade` 타입 확장 (`src/types.ts`) → `placeOrder` 시그니처 확장 (`src/store.ts`)
  - `OrderSheet.tsx`에 이유 칩·손절/목표가 UI — `index.css`의 미사용 `.reason-chips` 스타일이 이미 있음(디자인 목업 이식분)
  - 선행이던 [R0-1] `Trade[]` 보존은 ✅ 완료 — 판단 필드는 `SimRecord.trades`에 함께 실려 보존된다

### R6. 행동 이벤트 수집 (수익화 MVP 2단계)

> ✅ 구현됨 (2026-08-09) — 목업 브리프: [design-prompts/11-position-risk.md](../design-prompts/11-position-risk.md). `ActiveSim.events[]`: news/order(ms)/cancel/sl/tp/slhit

판단 전후의 행동 변화를 세션 이벤트 로그로 남긴다.

- `ActiveSim`에 `events[]` 추가: 뉴스 탭 열람·지표 카드 펼침, 주문 취소, 손절가·목표가 수정, 주문 결정 소요시간(시트 열림→제출), 캔들 진행 간격.
- 세션 종료 시 `SimRecord`에 보존. localStorage 1차 저장 + 로그인 시 서버 동기화(다른 기록과 동일 경로).
- 클릭 하나로 심리를 단정하지 않는다는 원칙(수익화방향 6장): 이벤트는 원시 기록만 하고 해석은 R7에서.

### R7. 행동 리포트 (수익화 킬러 기능)

> ✅ 구현됨 (2026-08-09) — 목업 브리프: [design-prompts/12-behavior-report.md](../design-prompts/12-behavior-report.md). 세션 리포트(회고 저장 직후, `src/lib/report.ts`) + 누적 리포트(`/report`, 지표별 잠금) + 지불의사 CTA(클릭 = `waitlistAt` 로컬 기록). **게이트 판정은 이제 데이터 수집 단계** — 세션이 쌓이면 신청 클릭률로 R8 착수 여부 결정

R5·R6 데이터로 과정 지표를 계산해 보여준다. **유료 전환의 aha 모먼트**가 이 화면이다.

- 과정 지표: 손절 기준 준수율, 손실 직후 거래 금액 변화, 수익/손실 거래 보유시간 비대칭, 뉴스 열람 후 판단 변경률.
- 표현 원칙: 심리 단정 금지, 관찰된 행동만 서술 (예: "손실 거래를 수익 거래보다 6배 오래 들고 있었습니다").
- **지불의사 검증 게이트**: 이 리포트를 본 유저가 결제(의사)를 보이는지가 R8 챌린지·시즌제 착수의 전제 (수익화방향 18장).
- R3보다 선행 — 거시 데이터가 필요 없고 R5·R6 데이터만으로 계산된다.

### R8. 챌린지 모드 (R7 게이트 통과 후)

주 수익원 후보인 기간제 챌린지의 로컬 프로토타입.

- 예: "14일 손절 훈련" — 규칙 제약(손절가 필수 입력, 세션 중 손절 변경 금지, 일일 세션 수 제한) + 진행률 + 완료 인증.
- 결제·예치금 모델은 v1.0(서버 전환) 시점. 그 전까지는 무료로 열어 **챌린지 완주율 데이터만 검증**한다.

### R9. Future 모드 (후순위, 개념 미정)

### R10. 재무 정보 탭

> ✅ 구현됨 (2026-08-10) — 3번째 탭 [재무]. `scripts/fetch-data.py` EDGAR 섹션 + `src/lib/fund.ts` + `FundPanel.tsx`. 목업 브리프 생략(기존 카드 토큰 재사용 — 시각 다듬기가 필요해지면 design-prompts/13으로 발주)

세션 중 현재 종목의 분기 재무(매출·영업이익·PER)를 제공한다. 이유 칩 '기업·실적'(R5)이 있는데 근거로 삼을 데이터가 없던 구멍을 채운다.

- **Point-in-time이 핵심**: 회계기간이 아니라 **공시일(SEC filed)** 이전 분기만 노출 — 실적 발표 전의 분기는 시뮬 시점에선 미래 정보다. 캔들이 공시일을 지나는 순간 카드에 나타난다(NEW 배지 7일).
- **분기 라벨도 상대 표기**('최근 분기'·'N분기 전') — "2023 Q3" 같은 절대 라벨은 날짜 마스킹(R0-2)을 무력화한다.
- 지표: 매출·영업이익 절대액, 매출 YoY, 영업이익률, 영업이익 YoY(음수 기저는 흑자전환/적자전환/적자지속), PER(TTM = 현재 캔들 종가 ÷ 최근 4개 공시 분기 EPS 합, 적자면 N/A).
- **절대액 노출은 의도적 선택**: 규모로 유명 종목을 추정할 수 있지만, 가격축 실가격 노출과 동급의 수용된 한계로 판단.
- 데이터: SEC EDGAR companyfacts(키 불필요) → `fundamentals.json`, 일일 파이프라인에 편입. 개별주 4종만 — ETF는 빈 상태. XBRL 이전(~2009) 구간은 "아직 공시된 재무가 없어요". EPS는 분할 조정(캔들 조정가와 기준 통일 — PER 성립 조건).
- 탭 열람은 R6 이벤트 `fund`로 수집. R7 "뉴스 후 판단 변경률"이 오염되지 않도록 `newsFollowups`에서 fund 이벤트는 건너뛴다.

### R11. 계정·기록 동기화 (개편 로드맵 Phase 3)

> ✅ 구현됨 (2026-08-10) — Supabase Auth(카카오·Google) + `records` 테이블(JSONB·RLS). `src/lib/supabase.ts`·`sync.ts`, 더보기 탭 계정 카드. 콘솔 셋업 절차는 `charty-web/README.md` 참조

Local-first 원칙(6장)을 유지한 채 로그인을 얹는다: **비로그인은 지금 그대로 전부 동작**, 로그인하면 기록이 계정에 저장되어 기기 간 이어진다.

- 동기화 대상은 **기록(SimRecord)만** — append-only·uuid 키라 병합이 id 합집합으로 끝나고 충돌 해결이 없다. 잔고는 최신 기록의 종료 잔고를 따라감. 진행 중 세션·커스텀 스타일·테마는 로컬 전용(v1).
- 서버는 덤 저장소: `records(id, user_id, ended_at, data jsonb)` + RLS(본인 것만). 스키마의 진실은 클라이언트 — 기록 구조가 바뀌어도 마이그레이션 없음.
- 대사 시점: 로그인/새로고침(전체 대사) + 회고 저장 직후(1건 push, 실패분은 다음 대사가 수습). 전체 초기화는 서버 기록도 삭제.
- env(`NEXT_PUBLIC_SUPABASE_URL`/`ANON_KEY`) 미설정이면 로그인 UI 자체가 숨음 — 설정 전 배포 안전.

### R12. 온보딩·계정 프로필

> ✅ 구현됨 (2026-08-10) — `/welcome`(첫 방문 게이트) + `/profile`(온보딩·수정 겸용) + `profiles` 테이블(RLS). 나이는 Google에서 받지 않음 — 생일은 People API 민감 스코프(앱 심사 필요)라 실익 없음, 연령대 직접 선택으로 대체

- **첫 방문 웰컴**: 기록·진행 세션이 없는 새 유저가 홈에 오면 `/welcome` — [Google로 시작하기] / [로그인 없이 둘러보기]. Local-first 원칙(6장) 유지가 결정 사항.
- **프로필 항목**: 닉네임(필수, 구글 이름 프리필) + 선택 5종 — 연령대(10대~60대+), 주요 시장(국내주식/해외주식/코인, 중복), 상품(현물/선물/옵션, 중복), 투자 스타일(단타/스윙/장기투자), 투자 경력(입문/1년 미만/1~3년/3년 이상). 필수를 닉네임 하나로 줄인 건 R5 마찰 최소 원칙과 같은 이유.
- **용도**: R3 종합 리포트의 개인화 맥락, 향후 코호트 분석(경력·시장 × R7 행동 지표), B2B(그룹 관리) 기반.
- 진입점별 복귀: 웰컴 로그인 → `/profile`(온보딩), 더보기 로그인 → `/more`(미작성이면 "프로필 설정하기" CTA 강조).
- 카카오 버튼은 Supabase 공개 설정을 읽어 **자동 활성화** — 대시보드에서 provider를 켜는 순간 코드 수정 없이 동작.

## 6. 원칙

- **Local-first**: 비로그인도 전체 기능이 동작하고, 데이터는 localStorage가 1차 저장소. 서버(Supabase)는 로그인 시 기록 동기화와 데이터 파이프라인(종목 확대·뉴스·홈 피드)용으로 최소 도입 — 파이프라인(Storage)·로그인 동기화(R11)로 도입 완료. (구 "서버 없음 유지" 원칙을 대체)
- **의존성 최소**: 현재 런타임 의존성 5개. 새 기능도 이 기조 유지.
- **블라인드 정책** (숨기는 것 / 보여주는 것):
  - 숨김: 종목명, 실제 날짜·연도, 시대 추정 가능한 사건·인물
  - 노출: 가격 움직임, 지표(EMA/볼밴/RSI/거래량), 경제지표의 수치와 방향성(R2), 기업 재무(매출·영업이익 절대액, YoY, 영업이익률, PER — 상대 분기 라벨, 공시일 이전 데이터만, R10)
  - 세션 완료 후에는 종목명 공개 (현재 구현됨. 날짜도 완료 후 공개로 통일)

## 8. 수익화 방향

> 아직 확정 스펙이 아닌 방향. R3까지 완성해 코어 가치를 증명한 뒤 착수.

**결론: 기간제 챌린지 우선 + 구독 + B2B 퍼널.** 상세 논리는 [차티앱수익화방향.md](./차티앱수익화방향.md) 2.5장·16장.
유사 검증 사례: TradeZella(저널 SaaS 구독, 월 $20~30), 챌린저스(예치금 기반 습관 챌린지 — 한국 시장 지불의사 검증).

| 구분 | 내용 | 담당 기능 |
|---|---|---|
| 무료 | 코어 루프(기본 3스타일·기본 종목·시뮬레이션·회고·기록) + **행동 리포트 첫 경험**(유료 전환 트리거) | R5·R6 수집 → **R7** |
| 챌린지 (주 수익원) | 14일 손절 훈련 등 기간제 프로그램. 예치금 모델 검토 | **R8** |
| 구독 (헤비유저) | **종합 리포트**(킬러 기능), 누적 행동 분석 심화, 데이터 확장(코인·국내주식·종목 추가), 커스텀 스타일 무제한 | **R3**·R7 심화 |
| B2B | 증권사 화이트라벨 연습 모드, 교육기관·투자동아리 그룹 | v1.0 이후 (계정·그룹 관리 필요) |

배제한 수단:
- **광고**: 니치 도구라 트래픽이 안 나오고, 연습 몰입을 해침.
- **일회성 영구 구매(buy once)**: 데이터를 지속 공급해야 하는 구조와 불일치. 기간제 챌린지는 시작·끝·성과 인증이 있는 프로그램 판매라 별개.

전제 조건이던 서버·계정은 개편 로드맵(Next.js + Supabase)에서 선행 도입 — 수익화 시점에는 결제만 얹으면 된다.

## 9. 장기 비전: 모의투자 플랫폼

> 아이디어 단계. 진입 순서: 연습앱 완성(→R3) → 수익화(챌린지·구독, v1.0) → 플랫폼. 플랫폼은 유저 없이는 콜드스타트로 실패하고, 연습앱은 혼자 써도 가치가 있어 유저 유입 경로가 된다.

### 컨셉
연습 기록 + **API로 검증된 실계좌 거래 기록**을 기반으로 노하우를 공유하는 커뮤니티.
차별점: "자칭 고수" 리딩방과 달리 수익 기록이 증권사·거래소 API로 검증됨 (해외 유사 사례: Collective2, eToro).
실계좌 연동은 "모의투자 행동이 실전과 같은가"라는 전이 의심 리스크([차티앱수익화방향.md](./차티앱수익화방향.md) 2.5장)의 장기 해답이기도 하다 — 연습 기록과 실전 기록을 같은 과정 분석으로 통합한다.

### 기능 스케치
- 실계좌 연동: 한국투자증권 KIS Developers, 업비트/바이낸스 API로 체결내역 조회
- 연습(차티 세션) + 실전 기록 통합 뷰
- 노하우 게시글에 검증된 기록 첨부, 팔로우

### ⚠️ 규제 리스크
- 대가를 받고 투자 노하우·종목 판단을 제공하면 **유사투자자문업 신고 대상**이 될 수 있음.
- "따라하기 매매"(카피 트레이딩)까지 가면 **투자일임업 라이선스** 영역.
- 타인의 증권사 API 키를 다루므로 보안·서버 인프라 필수.
- **플랫폼 수익 모델 확정 전에 법률 검토가 선행되어야 함.**
