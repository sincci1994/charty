# 차티(Charty) 기획서

> 개인 개발 로드맵용 문서. 코드 기준: `charty-web` v0.1.0 (2026-08 기준, Next.js 전환 후).
> 제품 방향성 개정: 2026-08-17. 기존의 "차트 판단 연습 앱"에서 **투자 인생 시뮬레이션 게임**으로 중심을 옮긴다.
> 화면별 기존 명세는 [`design-prompts/`](../design-prompts/)를 참조한다.

---

## 1. 제품 정의

**차티는 과거 시장에서 투자 인생을 빠르게 살아보며 나에게 맞는 매매법을 더 빨리 발견하고 검증함으로써, 투자 생애에서 더 이른 나이에 부자가 되는 것을 목표로 하는 투자 시뮬레이션 게임이다.**

**나에게 맞는 방법을 더 빨리 발견하고 검증하는 것은 수단이고, 더 빨리 부자가 되는 것이 목적이다.** 차티는 여러 시대의 실제 시장을 미래 정보 없이 압축 체험하고 수익·시간·위험을 함께 비교함으로써, 현실에서 수십 년이 걸릴 시행착오를 짧은 시간 안에 먼저 겪게 한다.

단, 이것은 제품 안에서 사용자가 추구하는 목표이지 실제 수익을 보장한다는 뜻은 아니다. 차티의 역할은 가장 빠른 한 번의 대박을 찾는 것이 아니라, **감당할 수 있는 위험 안에서 목표 자산에 더 일찍 도달할 가능성이 높은 자기 방법을 찾고 검증하게 하는 것**이다.

### 문제의식

- 실전에서 매매법 하나를 검증하려면 몇 달에서 몇 년이 걸리고, 실패 비용도 실제 돈으로 치러야 한다.
- 과거 차트 복기는 이미 결과를 아는 상태라 판단이 왜곡되고, 일반적인 백테스트는 규칙을 코드로 표현할 수 있어야 한다.
- 흔히 "우량주를 오래 보유하면 돈을 번다"고 하지만, 수익률만 보면 그 과정에서 **몇 년을 보냈는지**가 사라진다.
- 사람들의 실제 욕망은 노년의 큰 자산만이 아니라, 감당 가능한 위험 안에서 **더 이른 나이에 선택권을 얻는 것**에 가깝다.
- 단타의 빠른 결과와 장기투자의 높은 생존 가능성을 같은 기준으로 비교하려면 수익률뿐 아니라 소요 시간·최대 낙폭·파산 확률·재현성을 함께 봐야 한다.

### 핵심 통찰

차티에는 이미 다른 모의투자 앱과 구분되는 상호작용이 있다.

- 사용자가 정한 **주 타임프레임의 다음 캔들**을 누를 때만 시장 시간이 흐른다.
- 멈춘 시점에서는 여러 분석 타임프레임을 오가며 볼 수 있지만 미래 캔들은 볼 수 없다.
- 따라서 현실의 수개월·수년을 몇 분 안에 체험하면서도 각 시점의 결정은 직접 내릴 수 있다.

이 기능을 단순한 빠른 차트 재생이 아니라 **인생 시간의 압축**으로 해석하는 것이 새 방향의 출발점이다.

### 목표

1. **시간의 가격을 보이기** — 이 수익을 얻거나 잃는 동안 투자 인생이 얼마나 흘렀는지 체감시킨다.
2. **나만의 매매법 찾기** — 여러 보유 기간과 시장 국면을 짧은 실제 시간 안에 반복 경험하고 비교한다.
3. **운과 실력을 구분하기** — 한 번의 대박이 아니라 블라인드 구간 반복 검증을 통과한 규칙만 비법서로 남긴다.
4. **언제든 다시 하게 만들기** — 짧은 세션, 이어하기, 캐릭터 성장과 도전 목표로 게임처럼 진입하게 한다.
5. **연습을 다음 단계로 잇기** — 검증된 규칙을 실전 체크리스트, 공유 카드, 퀀트 규칙으로 확장할 수 있게 한다.

### 하지 않는 것

- 젊은 부자나 실제 수익을 보장하지 않는다.
- 높은 수익률만으로 좋은 전략이라고 평가하지 않는다.
- 거래 횟수나 접속 일수만으로 캐릭터를 성장시켜 과매매를 유도하지 않는다.
- 초기 버전에서 종목 추천, 자동매매, 카피 트레이딩을 제공하지 않는다.

### 1차 타깃

- 자신의 단타·스윙·장기투자 성향을 실제 돈 없이 비교해 보고 싶은 개인 투자자
- 차트는 볼 수 있지만 매매 규칙을 코드로 백테스트하기는 어려운 사람
- 긴 백테스트 리포트보다 직접 선택하고 결과를 체험하는 방식을 선호하는 사람

비로그인도 브라우저에서 핵심 기능이 동작하는 local-first 원칙은 유지한다.

## 2. 핵심 경험

### 2.1 시간의 규칙

차티에는 서로 섞으면 안 되는 세 종류의 시간이 있다.

| 시간 | 의미 | 제품 규칙 |
|---|---|---|
| 실제 플레이 시간 | 사용자가 앱을 사용한 현실의 분·시간 | 편의성과 몰입 지표로만 사용. 자산 성과에는 영향 없음 |
| 시뮬레이션 시간 | 과거 시장에서 캔들을 넘기며 흐른 시간 | 아바타의 나이, 목표 자산 도달 나이, 전략의 보유 기간에 반영 |
| 분석 타임프레임 | 멈춘 현재를 확대·축소해서 보는 차트 단위 | 시간을 진행시키지 않으며, 현재 커서 이후 데이터는 어떤 단위에서도 노출 금지 |

**주 타임프레임은 시계이고, 분석 타임프레임은 확대경이다.**

- 세션 시작 전에 사용자가 주 타임프레임을 정한다. 세션 중에는 공정한 비교를 위해 고정한다.
- [다음 캔들] 1회는 주 타임프레임 캔들 1개만큼 진행한다.
- 나이는 단순 클릭 수가 아니라 캔들의 실제 타임스탬프 차이로 계산한다. 휴장·주말 처리 등 세부 산식은 D0에서 확정한다.
- 분석 차트의 큰 시간봉은 현재 시점까지만 잘린 미완성 봉 또는 완료된 봉만 사용해 미래 누출을 막는다.

### 2.2 투자 생애와 아바타

아바타는 꾸미기용 보상이 아니라 **시간과 자산의 결과를 한눈에 보여주는 장치**다.

- 가로축: 시작 나이부터 누적된 시뮬레이션 시간
- 세로축: 현재 순자산과 목표 자산 대비 진행률
- 외형 변화: 연령 단계 + 자산 단계 + 주요 사건(목표 달성, 큰 낙폭, 재기)
- 결과 표현: "수익률 +24%"보다 먼저 **"2년 7개월을 써서 자산이 1,000만 원에서 1,240만 원이 됐어요"**를 보여준다.
- 동일한 시장 구간의 매수후보유 결과도 같은 나이 축에 겹쳐 보여준다.

캐릭터의 실력 성장은 단순 자산과 분리한다. 자산은 운으로 급등할 수 있지만, 실력 등급은 계획 준수·반복 검증·위험 관리 증거가 쌓여야 오른다.

### 2.3 두 가지 플레이 단위

| 단위 | 역할 | 종료 |
|---|---|---|
| **세션** | 현재 구현된 한 번의 블라인드 차트 연습. 특정 기간·종목·시점에서 거래 | 기간 종료 또는 사용자의 종료 |
| **투자 생애(Run)** | 여러 세션을 연결해 자산과 나이가 계속 이어지는 게임 단위 | 목표 자산 달성, 은퇴 나이 도달, 파산 또는 자발적 종료 |

표준 생애와 개인 생애를 분리한다.

- **표준 생애**: 모두 같은 시작 나이·시작 자산·데이터 조건을 사용한다. 시즌·랭킹·공유에 적합하다.
- **개인 생애**: 사용자가 현재 나이·자산·목표를 설정한다. 자기 계획 탐색용이며 공개 순위에는 넣지 않는다.

독립 연습 세션은 지금처럼 임의의 블라인드 구간을 뽑아도 된다. 반면 투자 생애는 시작 시점을 한 번 정한 뒤 **시간을 되돌리거나 무관한 시대로 건너뛰지 않고 순서대로 진행**해야 한다. 그래야 아바타의 나이와 자산 경로가 실제 하나의 생애라는 의미를 가진다.

초기 기본값은 현재 엔진의 시작 잔고 1천만 원을 유지한다(2026-08-15에 100만→1천만 변경). 표준 시작 나이와 목표 자산은 D0 사용자 테스트에서 확정한다. 단, 표준 생애는 "모두 같은 시작 자산"이 전제이므로 현재의 세션 간 잔고 이월 구조와 양립하지 않는다 — 표준 생애는 잔고 이월을 끊고 고정 시작 자산에서 출발한다는 규칙을 D0에서 확정한다.

### 2.4 코어 루프

1. **목표 설정** — 시작 나이·자산, 목표 자산, 주 타임프레임과 시험할 비법서 후보를 고른다.
2. **블라인드 분석** — 종목·날짜·미래를 모른 채 여러 분석 타임프레임과 당시 공개된 뉴스·재무를 살핀다.
3. **판단과 진행** — 매수·매도 이유와 위험 계획을 기록하고 다음 캔들로 투자 인생을 진행한다.
4. **즉시 체감** — 자산, 나이, 생활 단계의 아바타가 함께 변한다.
5. **세션 회고** — 사용한 시간, 수익, 낙폭, 계획 준수, 같은 구간의 매수후보유 결과를 비교한다.
6. **비법서 갱신** — 잘된 이유를 규칙으로 저장하거나 기존 규칙의 증거 한 건으로 추가한다.
7. **다른 시대에서 재검증** — 충분히 다른 블라인드 표본에서도 살아남는지 다시 시험한다.

이 루프에서 게임성은 분석을 가리는 별도 미니게임이 아니라, **시간을 쓰고 성장하며 전략을 완성하는 과정 자체**에서 나온다.

### 2.5 성과 판정

"가장 젊은 부자"만 강조하면 고위험 몰빵이 최적 행동이 된다. 따라서 성과는 다음 순서로 본다.

1. 목표 자산 도달 여부
2. 목표 도달 시 시뮬레이션 나이
3. 최대 낙폭과 파산 여부
4. 같은 표본의 매수후보유 대비 초과 성과
5. 다른 시장 구간에서의 반복 재현성

단일 점수는 공유와 게임 진행에만 사용하고, 판단 근거가 되는 원지표는 항상 함께 보여준다. 표본이 적을 때는 "검증됨" 대신 "관찰 중"으로 표시한다.

## 3. 비법서 시스템

비법서는 멋있는 문구 모음이 아니라 **사용자가 세운 가설과 그 가설을 지지하거나 반박하는 플레이 증거의 묶음**이다.

### 비법서 한 장의 구조

| 항목 | 예시 |
|---|---|
| 적용 시장·국면 | 미국 대형주, 상승 추세, 변동성 보통 |
| 주 타임프레임 | 4시간봉 |
| 분석 타임프레임 | 1시간봉·1일봉 |
| 진입 조건 | 일봉 추세 상승 + 4시간봉 눌림 |
| 청산 조건 | 목표가, 손절가, 추세 훼손 |
| 위험 규칙 | 거래당 자산 2% 이내 손실 |
| 금지 조건 | 주요 발표 직전, 거래량 급감 구간 |
| 검증 증거 | 표본 수, 중앙 수익률, 최대 낙폭, 목표 도달 나이, 매수후보유 대비 |

### 성장 단계

1. **메모** — 한 세션에서 얻은 아이디어. 아직 전략으로 취급하지 않는다.
2. **초안** — 진입·청산·위험 조건을 사용자가 명시했다.
3. **검증 중** — 서로 다른 블라인드 구간에서 같은 규칙을 반복 사용한다.
4. **검증 배지** — 최소 표본 수와 위험 기준을 충족했다. 수익 보장이 아니라 앱 안의 반복 시험을 통과했다는 뜻이다.

배지 기준은 수익률만으로 정하지 않는다. 표본 수, 시장 국면 다양성, 최대 낙폭, 파산률, 계획 준수율, 벤치마크 대비를 함께 사용한다.

### 활용 경로

- **플레이**: 다음 생애에서 비법서를 장착하고 규칙 체크리스트를 보며 거래한다.
- **자랑·공유**: 수익 숫자만 잘라낸 인증이 아니라 사용한 시간·위험·표본 수가 포함된 결과 카드를 공유한다.
- **실전 보조**: 실제 주문 전 확인하는 읽기 전용 체크리스트로 사용한다.
- **퀀트 연계**: 조건을 구조화한 JSON 또는 Python/Pine 초안으로 내보내 백테스트의 출발점으로 삼는다.

자동매매 연결과 유료 비법서 판매는 초기 범위에서 제외한다. 규칙이 기계적으로 표현 가능한지, 금융 규제와 책임 범위를 어떻게 다룰지 먼저 검증해야 한다.

## 4. 현재 구현 기반 (v0.1.0)

새 방향은 처음부터 다시 만드는 것이 아니라 현재 구현을 기반으로 확장한다.

### 기술 스택

| 항목 | 선택 |
|---|---|
| 프레임워크 | Next.js 16 (App Router) + React 19 + TypeScript |
| 차트 | lightweight-charts v5 (캔들·거래량·EMA·볼밴·RSI) |
| 상태/저장 | zustand + persist, localStorage 키 `charty`; 로그인 기록은 Supabase 동기화 |
| 데이터 수집 | `charty-web/scripts/fetch-data.py` + GitHub Actions + Supabase Storage |
| 테스트 | vitest (`engine`·`data`·`fund`·`report`·`sync`) |

### 구현된 핵심 흐름

- 홈 → 스타일 선택 → 블라인드 시뮬레이션 → 회고 → 기록/행동 리포트
- 기본 3스타일(단타·스윙·장기)과 커스텀 기간·타임프레임
- 멈춘 현재 시점에서 멀티 타임프레임 분석, 상대 시간축, 미래 데이터 차단
- 지정가 현물 매수·매도, 주문 이유·손절가·목표가 기록
- 경제지표·뉴스·point-in-time 기업 재무
- 세션별 체결·행동 이벤트 저장과 행동 리포트
- Google/카카오 계정 기반 기록 동기화, 프로필, 비로그인 local-first 사용

### 현재 데이터와 규칙

- 30종목 · 6세트 (`data.ts` `SETS`) — 빅테크(QQQ·SPY·AAPL·NVDA·TSLA·MSFT), 반도체·AI(AMD·INTC·MU·TSM·AVGO·QCOM), S&P500 우량주(JPM·JNJ·KO·XOM·CAT·DIS), 러셀 스몰캡(CROX·GPRO·IRBT·FSLR·KTOS·SFIX), 꿈팔이 성장주(PLUG·FCEL·LCID·RIVN·JOBY·IONQ), 랜덤(전체). 스몰캡·우량주 추가로 생존 편향이 완화되고 블라인드가 강해짐

|---|---|---|
| 5분 | 약 60거래일 **롤링** | yfinance 분봉 제한. 갱신 시 과거 구간이 소실됨 |
| 1시간 | 약 2년 | |

- 시작 잔고 ₩1천만, 지정가 주문 — 깊이 가중 참여율 체결(거래량 반영·부분체결·이월, engine.ts `CAP` 10%), 편도 수수료 0.1%(`FEE`), 잔여 포지션은 세션 종료 종가 전량 청산(유동성 예외)

## 5. 방향 전환 후 로드맵

기존 R1·R2·R5·R6·R7·R10·R11·R12는 구현 기반으로 유지한다. 앞으로의 우선순위는 아래 D(Direction) 로드맵을 따른다.

### D0. 시간·비교 규칙 확정

코드보다 먼저 결과의 의미를 고정한다.

- **통화 단위 정합** ✅ 구현됨: "가격·차트는 $ 표기 유지, 현금·자산·손익은 ₩" — 환전은 체결·평가의 현금 경계에서만 고정 환율 `FX=1400`(engine.ts)으로. 기존 잔고·기록 스케일이 보존되고 PER($÷$)도 그대로 성립. 당시 환율이 아닌 근사치임은 주석 명시
- **5분봉 아카이브 누적(즉시 실행)**: 5분봉은 60일 롤링뿐이라 단타의 "여러 시대 반복 검증"(D4)이 물리적으로 불가능하다. 수집 파이프라인이 스냅샷을 덮어쓰지 말고 누적(append)하도록 지금 바꿔야 1년 뒤에 표본이 생긴다
- **체결 규칙** ✅ 구현됨: 편도 수수료 0.1%(`FEE`, 현금에만 차감·pnl은 gross). 슬리피지는 시장가 도입(D6) 전에는 지정가 전용 엔진에서 정의상 불성립이므로 만들지 않는다
- **유동성(깊이 가중 참여율)** ✅ 구현됨: 체결 가능 수량 = floor(캔들 거래량 × depth × `CAP` 10%), depth = 내 지정가보다 유리하게 거래된 봉 구간 비율. 저가/고가를 정확히 터치한 봉은 depth 0 → 미체결(관통 체결 규칙을 포함), 유동성 부족분은 다음 캔들로 이월(부분체결), 같은 캔들의 여러 주문은 v×CAP 예산을 공유. 세션 종료 강제청산만 전량 체결 예외
- **표준 생애의 잔고 규칙**: 표준 생애는 세션 간 잔고 이월을 끊고 고정 시작 자산에서 출발한다(현재 이월 구조와 비양립)
- 캔들 사이 휴장·주말을 아바타 나이에 포함하는 방식 (현재 R13 구현은 달력 기준 — 주말·밤 포함)
- 표준 생애의 시작 나이·시작 자산·목표 자산·은퇴 나이
- 목표를 명목 금액이 아닌 시작 자산 배수 또는 현재 구매력으로 비교하는 방식
- 세션의 동일 종목 매수후보유와 생애의 광범위 시장 ETF 매수후보유 벤치마크 산식
- 배당·주식분할 등 기업행동과 가격 데이터의 기준 통일 — 현재 데이터는 back-adjusted 총수익 기준이므로 "배당 재투자 반영·세금 미반영"을 명시하고, 회고에 세후 근사(양도세 22%·250만 원 공제) 병기를 검토
- 최대 낙폭·파산·목표 도달 나이 계산
- 랜덤 표본 중복 방지와 시장 국면 분산 기준
- 미래 누출 방지를 위한 분석 타임프레임 봉 처리 기준
- 표준 생애에서는 추가 입출금을 금지하고, 개인 생애의 정기 투자금은 별도 기록하는 원칙

**완료 조건:** 고정된 세션 기록 하나로 나이와 모든 비교 지표를 항상 동일하게 재계산할 수 있다.

### D1. 시간 HUD와 결과 아바타 — 방향성 MVP

홈 아바타·누적 차트시간·경과시간 표기는 R13·R14로 **이미 출시됐다**. D1은 새로 만드는 단계가 아니라, 기출시분이 재도전을 만드는지 확인하면서 아래 최소 신규분만 얹는 단계다.

이미 출시 (검증 대상):
- 홈 아바타(나이×부 단계), 누적 차트시간, "이만큼 모으는 데 매매로 보낸 시간" 문구, 자산 추이

신규 개발 (4개로 축소):
1. 시뮬레이션 상단 나이·경과 시간 HUD + 회고 첫 문장을 "얼마의 시간을 써서 어떻게 됐나"로 변경
2. 같은 구간 매수후보유 결과·최대 낙폭 비교 — 현재 코드에 전무한 유일하게 큰 조각
3. 주문 시트에 "이 주문은 이 봉 거래대금의 X%" 캡션 한 줄 — 체결 로직 무변경, 유동성 감각을 표시로 먼저
4. 초경량 비법서 카드 — 기존 주문 이유 칩·손절·목표 기록에 스타일·타임프레임을 묶어 저장하고 다음 세션에서 재장착. 북극성의 대리 지표(카드 재사용)를 v0.7부터 측정하는 장치
5. ✅ AI 해석 카드 (구현됨, 전용 그라디언트 디자인) — 뉴스·재무 탭 상단에 초심자용 해석: 거시(금리 수준·방향 × 물가 × VIX 존)와 재무(매출·이익 상태 × PER 밴드 × 거시 교차 → 펀더멘털 판정). LLM이 신호 조합별 문장을 생성해 코퍼스로 큐레이션(`lib/coach.ts`), 런타임은 신호 조회만 — 서버·비용 0, 시대·연도 어휘는 테스트로 차단. 항상 "경향" 서술·매매 지시 금지(§6·유사투자자문 경계), 더보기 토글로 off 가능. 판단 순간 UX의 첫 조각

아바타 개선은 에셋 추가가 아니라 매핑 변경으로 — 부 단계를 절대 10억 컷 대신 **목표 자산 대비 진행률**(5~6단계)로 나눠, 1.6배~100배 구간에서 아바타가 전혀 변하지 않는 무반응 구간을 없앤다.

아바타 시작 모습은 프로필 연령대·성별을 시드로 사용한다(§2.3 개인 생애 "시작 나이"의 첫 구현, 구현됨) — 연령대 대표 나이 + 시뮬 경과의 절대 나이로 단계를 정하고(30 미만 학생 / 30~59 어른 / 60+ 노년), 성별 세트는 에셋이 준비되는 대로 파일만 추가하면 반영된다.

**검증 질문(행동형):** 세션 종료 후 스스로 다른 스타일·타임프레임으로 재시작하는가? 비법서 카드를 만들고 한 번이라도 재장착하는가?

### D2. 투자 생애(Run)와 게임 루프

**선행 조건 — 아바타·엔딩 작업보다 먼저 확정:**

- 포지션 이월: 생애 세션은 종료 시 전량 강제청산을 부르지 않고 포지션을 다음 세션으로 승계한다(`SimRecord`에 포지션 저장 포함). 이게 없으면 생애 안에서 장기 보유가 구조적으로 불가능하다
- 블라인드 규칙 변경: 순차 생애는 2회차 세션부터 종목·시대가 이미 공개되므로 §6의 블라인드와 양립하지 않는다. 생애 모드는 "종목만 은닉, 시대는 공개"로 하고, 블라인드는 D4 검증실 전용 규칙으로 격리한다
- 페이싱: 생애(Run)는 데이터가 20년치인 1일·1주봉 기반으로 설계하고, 단타(5분봉)는 생애가 아니라 "며칠짜리 에피소드"로 분리한다 — 5분봉 세션은 시뮬 시간 1거래일이라 생애의 나이가 사실상 흐르지 않는다
- 진행 수단: "손절/목표 도달까지 진행" 버튼(자동 체결이 아니라 도달 캔들에서 정지). 홀딩 노동을 없애고 멈추는 순간을 긴장 이벤트로 만든다

**본 기능:**

- 표준 생애 / 개인 생애 생성
- 생애 시작 시 시대를 한 번 정하고 이후 시장 시간을 순차 진행 (시대 공개·종목 은닉)
- 세션 간 나이·자산·목표·사용 전략 이어가기
- 목표 자산 달성, 은퇴, 파산, 중도 종료와 엔딩 카드
- 짧게 한 캔들 또는 한 세션만 진행하고 언제든 이어하기
- 동일 조건의 시즌 시드와 개인 최고 기록
- 자산 레벨과 별개인 실력 레벨: 계획 준수·위험 관리·검증 횟수로 성장

리더보드는 표본 조건이 같은 표준 생애에만 검토한다. 개인 생애의 실제 나이·자산은 기본 비공개다.

### D3. 수동 비법서 MVP

- 기존 주문 이유를 비법서의 진입·청산·위험 규칙으로 확장
- 비법서 생성·편집·버전 관리
- 세션 시작 시 시험할 비법서 선택, 주문 시 체크리스트 표시
- 세션 종료 후 규칙 준수 여부와 증거 연결
- 메모 → 초안 → 검증 중 상태

처음부터 AI가 전략을 만들어 주거나 자유 문장을 자동매매 코드로 바꾸지 않는다. 사용자가 자신의 규칙을 명확히 쓰고 실제로 지켰는지를 먼저 해결한다.

### D4. 블라인드 검증실

- 서로 다른 종목·시대·시장 국면에서 같은 비법서를 반복 시험
- 최소 표본 수, 중복 표본 방지, 국면별 결과 표시
- 중앙 수익률·최대 낙폭·파산률·목표 도달 나이·벤치마크 대비 계산
- 데이터가 부족한 전략에는 명확한 불확실성 표시
- 기준 충족 시 검증 배지와 아바타 실력 성장
- 5분봉 기반(단타) 비법서는 아카이브가 충분히 쌓이기 전까지 검증 배지 대상에서 제외하고 "관찰 중"까지만 허용 — 60일 롤링 데이터로는 시대·국면 다양성이 성립하지 않는다

기존 R3 종합 리포트의 거시경제 분석은 이 단계에 흡수한다. "어떤 상황에서 이 전략이 통했는가"를 설명하는 보조 증거로 사용한다.

### D5. 공유·챌린지·시즌

- 나이·자산·낙폭·표본 수를 함께 담은 생애 결과 카드
- 비법서 공개 프로필과 버전별 검증 이력
- "30세 전에 목표 도달", "최대 낙폭 20% 이내" 같은 규칙형 도전
- 같은 데이터 시드를 사용하는 시즌 도전
- 친구와 결과 비교. 거래 지시보다 과정과 증거를 중심으로 표현

기존 R8의 "14일 손절 훈련"은 보조 챌린지로 유지할 수 있지만, 첫 게임 모드는 **가상 나이와 목표 자산을 사용한 투자 생애 도전**이 된다.

### D6. 실전·퀀트 브리지

- 검증된 비법서의 실전 주문 전 체크리스트
- 모의 기록과 실제 체결 기록을 같은 규칙으로 비교
- 기계 판독 가능한 규칙 스키마와 내보내기
- Python/Pine 전략 초안 또는 외부 백테스트 도구 연동
- 자동 실행 전 별도 샌드박스와 안전·법률 검토

실계좌와 퀀트 연계는 코어 루프의 종착점이지 초기 획득 기능이 아니다. 먼저 사용자가 비법서를 만들고 반복 검증하는 행동이 실제로 발생해야 한다.

### 기존 미완료 항목 재판정

| 기존 항목 | 결정 |
|---|---|
| R3 종합 리포트 | D4에 흡수. 전략이 통하는 국면을 설명하는 증거로 재정의 |
| R4 스피드 퀴즈 | 보류. 시간·자산·비법서 루프와 연결되지 않는 독립 미니게임은 우선하지 않음 |
| R8 챌린지 | D5로 재정의. 실제 14일 습관보다 투자 생애 목표를 먼저 검증 |
| R9 Future 모드 | 후순위 유지. 숏·레버리지는 젊은 부자 목표에서 위험 몰빵을 부추길 수 있어 별도 규칙 필요 |
| 기존 행동 리포트 | 유지하되 킬러 기능이 아니라 비법서와 실력 성장의 보조 증거로 사용 |

### 집행 현실성 트랙

판단 보조(지표·재무·뉴스)는 이미 충분히 구현돼 있고, 집행 계층(체결·비용·유동성)은 코드에 없다. 호가창 시뮬은 만들지 않는다 — 아래 사다리로 충분하다.

| 시점 | 장치 | 상태 |
|---|---|---|
| D0 | 통화 단위 정합(가격 $·현금 ₩, FX 경계 환산) + 편도 수수료 0.1% | ✅ 구현 |
| D0 | 깊이 가중 참여율 체결(터치 미체결·부분체결·이월 포함) — 계획보다 앞당겨 전 종목 적용 | ✅ 구현 |
| D1 | 주문 시트 "이 주문 = 직전 캔들 거래대금의 X%" 캡션 + 10% 초과 부분체결 예고 | ✅ 구현 |
| D6 | 시장가 주문 + 슬리피지 (그 전에는 정의상 불성립) | 예정 |

## 6. 제품 원칙

- **시간이 1급 데이터다**: 모든 수익 결과에는 그 결과를 만드는 데 사용한 시뮬레이션 시간이 붙는다.
- **빠른 체험, 느슨하지 않은 검증**: 플레이는 빨라야 하지만 전략 인증 기준은 엄격해야 한다.
- **수익과 실력을 분리한다**: 자산 증가는 결과이고, 실력 성장은 반복성·계획 준수·위험 관리의 증거다.
- **블라인드 유지**: 세션 중 종목명, 실제 날짜·연도, 시대를 특정할 사건·인물은 숨긴다. 완료 후 공개한다. 단, 순차 진행하는 생애 모드는 2회차부터 시대가 이미 공개되므로 "종목만 은닉"으로 완화한다(D2 선행 조건 참조) — 완전 블라인드는 D4 검증실 전용 규칙이다.
- **미래 정보 금지**: 뉴스·재무·상위 시간봉을 포함해 당시 알 수 없던 정보는 표시하지 않는다.
- **벤치마크를 숨기지 않는다**: 적극 매매가 같은 기간의 단순 보유보다 나았는지 항상 비교할 수 있게 한다.
- **운을 자랑으로 포장하지 않는다**: 공유 결과에 시간·낙폭·파산 여부·표본 수를 포함한다.
- **게임이 과매매를 보상하지 않는다**: 거래 횟수, 레버리지, 접속 스트릭을 핵심 성장 조건으로 두지 않는다.
- **Local-first**: 비로그인도 핵심 기능이 동작하고 localStorage가 1차 저장소다. 로그인은 동기화와 장기 보존을 돕는다.
- **의존성 최소**: 새 기능도 현재의 가벼운 클라이언트 중심 구조를 우선한다.

## 7. 성공 지표와 검증 순서

### 북극성 지표

**반복 검증 행동률**: 비법서 초안을 만든 사용자가 다른 블라인드 표본에서 같은 비법서를 다시 시험한 비율.

단순 세션 수보다 이 지표가 중요한 이유는 차티의 최종 가치가 "차트를 많이 넘김"이 아니라 "자기 규칙을 만들고 검증함"에 있기 때문이다.

단, 이 지표는 D3~D4가 나와야 관측 가능하다. v0.7~v0.8 구간에서는 D1의 초경량 비법서 카드로 **대리 지표(카드 생성 수, 같은 카드 2회 이상 재사용 수)**를 먼저 측정하고, 반복 검증 행동률은 v1.0 목표 지표로 둔다.

또한 사용자가 적은 1인 개발 단계에서 비율(~율) 지표는 분모가 없어 성립하지 않는다. D1~D2 검증은 "실사용자 10명 중 몇 명이 스스로 4번째 세션을 시작했는가" 같은 절대수로 판정한다.

### 단계별 지표

| 단계 | 확인할 행동 |
|---|---|
| D1 방향성 MVP | 첫 세션 완료 수, 시간/아바타 결과 확인 수, 다른 타임프레임 재도전 수, 매수후보유 비교 확인 수 |
| D2 투자 생애 | 생애 생성 대비 2번째 세션 진입률, 생애 완료율, 새 생애 시작률 |
| D3 비법서 | 세션 후 비법서 초안 생성률, 다음 세션에서 같은 비법서 장착률 |
| D4 검증실 | 반복 검증 행동률, 표본 5개 이상 누적 비법서 수, 벤치마크 비교 확인율 |
| D5 공유 | 증거 포함 결과 카드 공유율, 시즌 재참여율 |
| D6 브리지 | 체크리스트 재사용률, 규칙 내보내기율, 모의-실전 비교 유지율 |

### 가장 먼저 검증할 가설

1. 수익률만 보여줄 때보다 나이·자산 아바타를 함께 보여줄 때 다음 세션 의향이 높아진다.
2. 사용자는 "단타 vs 장기" 논쟁보다 "목표 자산에 몇 살에 도달했나" 비교를 더 직관적으로 이해한다.
3. 벤치마크와 낙폭을 함께 보여줘도 재미가 줄기보다 결과에 대한 신뢰가 높아진다.
4. 사용자는 성공한 한 판을 저장하는 데서 끝나지 않고 같은 규칙을 다른 시대에 다시 시험한다.

1~2가 확인되기 전에는 고비용 캐릭터 제작과 커뮤니티를 확장하지 않는다. 4가 확인되기 전에는 퀀트·실계좌 연계를 개발하지 않는다.

## 9. 수익화 방향

기존의 "행동 리포트가 곧 유료 전환의 킬러 기능"이라는 가정은 더 이상 제품 방향의 중심 전제가 아니다. 새 퍼널은 **투자 생애 체험 → 비법서 초안 → 반복 검증 → 더 깊은 검증과 활용**이다.

| 구분 | 제공 가치 |
|---|---|
| 무료 | 기본 시뮬레이션, 시간·아바타 결과, 표준 투자 생애, 기본 비법서와 소수 표본 검증 |
| 구독 | 비법서·생애 슬롯 확장, 국면별 심화 검증, 고급 비교 리포트, 규칙 내보내기, 실전 체크리스트 이력 |
| 시즌·챌린지 | 같은 조건의 기간제 생애 도전, 특별 엔딩·외형·인증 카드. 실력에 영향을 주는 유료 아이템은 제외 |
| B2B | 증권사·교육기관용 투자 생애 시뮬레이션, 그룹 과제와 검증 리포트 |

유료화 전에 확인할 순서는 다음과 같다.

1. 시간·아바타 표현이 재도전을 만드는가
2. 투자 생애가 반복 플레이를 만드는가
3. 비법서를 실제로 작성하고 다시 사용하는가
4. 더 많은 검증 표본과 활용 도구에 지불 의사가 있는가

광고는 몰입을 해치고, 확률형 아이템은 투자 위험과 결합될 때 부적절하므로 배제한다. 비법서 판매·구독자 전용 종목 추천·카피 트레이딩은 금융 규제 검토 전에는 수익 모델에 넣지 않는다.

상세 수익화 문서 [`차티앱수익화방향.md`](./차티앱수익화방향.md)는 기존 행동 리포트 중심 가정을 담고 있으므로, D1 가설 검증 후 새 퍼널에 맞춰 별도로 개정한다.

## 10. 장기 비전

차티의 장기 확장은 기능을 많이 붙이는 플랫폼화가 아니라 **한 사람의 전략이 아이디어에서 실전 가능한 규칙으로 성장하는 경로**를 완성하는 것이다.

1. 과거 시장을 직접 살아본다.
2. 시간과 위험을 포함한 결과를 본다.
3. 자기 규칙을 비법서로 쓴다.
4. 다른 시대와 시장에서 반복 검증한다.
5. 체크리스트나 퀀트 규칙으로 구조화한다.
6. 실제 체결 기록과 모의 결과의 차이를 확인한다.
7. 증거가 붙은 전략과 투자 생애를 다른 사람에게 공유한다.

실계좌 연동은 한국투자증권 KIS Developers, 업비트·바이낸스 등의 읽기 전용 체결 조회부터 검토한다. 주문 실행 권한은 별도 보안·안전성 검증 전에는 다루지 않는다.

### 규제·신뢰 원칙

- 대가를 받고 구체적 종목 판단이나 매매 신호를 제공하면 유사투자자문업 등 금융 규제 검토가 필요하다.
- 따라하기 매매와 자동 집행은 투자일임·보안 책임 영역으로 확장될 수 있다.
- 공유되는 비법서는 미래 수익 보장이 아니라 과거 블라인드 표본에서의 검증 기록임을 명시한다.
- 플랫폼 수익 모델과 실제 주문 연동을 확정하기 전에 법률·보안 검토를 선행한다.
